# Phased Implementation Plan

Locked stack (AGENTS §3): Python 3.14 · FastAPI · Pydantic v2 · SQLAlchemy 2 · Alembic · SQLite · React+TS (Vite) · WebSockets · Docker Compose · offline AI providers.

## Phase 1 — Foundations (current)
- Backend scaffold: `uv`-managed deps, pinned; ruff + mypy + pytest.
- Canonical Pydantic domain models; SQLAlchemy tables; Alembic migration.
- AODB/AIDX adapters passing fixture tests; ACRIS-shaped mock feed (fixture dir absent, documented).
- Deterministic seed: full-mode synthetic day (~900 legs via adapter) + reference mode; airport layout; screens/outlets/campaigns; 30-day history.
- Simulation engine: single FastAPI-worker lifecycle; 15 s slot cadence; injection while paused; broadcast bus (WS).

## Phase 2 — Vertical slice
- Presence (5-min ZonePresence, per-flight profiles, immediate-event recalc).
- Decision pipeline (filters → scores → rules → validation → audit log), delay-trigger scoring, worked-example calibration regenerated by the real engine.
- Virtual playback (backend owns plays/impressions), promo tokens + QR, mobile claim (idempotent, family second code), retail metrics learning.
- Airline / Retailer / Passenger screen React views on shared WS state; delay chain <2 s wall.

## Phase 3 — Mandatory role workflows
- Admin (map, KPIs, incident tracker, master data forms, decision log search).
- Media Manager (inventory calendar, pricing, approval, conflicts, advertisers).
- Retailer full (campaign builder, creatives, codes, history/duplicate).
- Airline full (flights/timeline, gate messaging, delay goodwill co-funding).
- Transparency surfaces per role (§12).

## Phase 4 — Demo polish
Split-screen mode, creative assistant (offline providers), tomorrow-slot recommendations, i18n + white-label, time-jump/reset UX, performance tuning (60×), receipts.

## Phase 5 — Submission
Acceptance checklist run (docs/REQUIREMENT_CHECKLIST.md), docs (adapter guide/architecture/OpenAPI/WS contract), compose hardening, rehearsal script.

## Milestone M1 (this working session)
Docker Compose up → seeded ~900 legs/180 screens/40 outlets → shared clock → Gate-42-style delay demo: flight update → presence bump → decision swap → QR → phone claim → retailer redemption/revenue — with the worked-example engine regression test green.

## Engineering principles applied
- One engine, serialized control commands, idempotent event application; async SQLite via aiosqlite with short transactions; no blocking loops on the event loop (CPU work in executor pools).
- Adapters → canonical entities only; decisions grounded in persisted EvidenceRecords; AI provider interfaces with offline mocks behind feature flags/timeouts.
- Frontend renders; never computes presence/scores/eligibility/budgets/revenue.
